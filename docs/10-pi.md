# 10 - Using pi with this kit

pi is a small, extensible coding agent for the terminal
([pi.dev](https://pi.dev), package `@earendil-works/pi-coding-agent`). You
are using it as your second agent, and your short-loop workflow is written
for both: **a game set up with this kit works the same in pi, in Claude Code
and in the Code tab of Claude Desktop**, because everything that matters lives
in plain files in the game's folder, and the commands are installed for both
([workflow/WORKFLOW.md](../workflow/WORKFLOW.md), section 6).

Written against pi 1.5.2 (November 2026). pi moves fast; when something here
disagrees with pi's own docs, pi's docs win.

## Read this first: what pi costs with a Claude Pro subscription

- Your Pro allowance covers Anthropic's own apps: Claude Desktop (chat and the
  Code tab) and the Claude Code command line.
- pi can sign in with a Claude subscription (`/login`), but Anthropic bills
  third-party tools separately: pi itself warns at startup that this usage
  "draws from extra usage and is billed per token". In other words, **in pi
  your Pro plan does not give you its included usage**; you pay on top, at API
  rates, and only if extra usage is switched on in your Claude account.
- The rules changed several times during 2026. Before relying on any of this,
  look at the usage page in your Claude account settings and at what pi prints
  when you sign in.

What that means for a small budget:

| Agent | Paid by | Use it for |
|---|---|---|
| Claude Desktop Code tab / Claude Code | the Pro plan you already have | the bulk of `/spec`, `/start` and `/qa` |
| pi + Anthropic sign-in or API key | per token, on top of Pro | when you want pi specifically; set a spending limit first |
| pi + another provider (`/login` lists them: OpenAI/ChatGPT sign-in, GitHub Copilot, OpenRouter, Gemini, DeepSeek and more) | that provider | learning pi; cheap bulk work the tests can judge |
| pi + a local model (llama.cpp) | electricity | experiments only: a GTX 1650 with 4 GB runs models far too small for reliable agent work |

Because the harness decides whether work is correct, a cheaper model is a
reasonable choice for mechanical slices (see "nth of a kind" in
[09-loops.md](09-loops.md)): a wrong result fails a test instead of slipping
through. Reading your design and writing the spec (`/spec`) is where the
strongest model you have is worth it.

pi shows what a session has cost in its footer and with `/session`.

## Where to run pi

pi does **not** ask before it runs a command or edits a file, and it has no
sandbox: it can do whatever your user account can do. That is by design. So:

- **Run it on the Mint box, as the `agent` user** ([03-setup-mint.md](03-setup-mint.md)).
  That user has no sudo and none of your files, which is exactly the
  "dedicated user account" option in pi's own security guide.
- On the Windows laptop, run it only in a game folder that is committed and
  pushed, or inside WSL. Windows 10 no longer gets security updates
  ([01-machines.md](01-machines.md)); an agent without permission prompts is
  one more reason to keep serious agent work off it.
- The guard extension below is a seatbelt, not a wall.

## Install

On Mint, as the `agent` user:

```bash
curl -fsSL https://pi.dev/install.sh | sh
```

```bash
pi --version
```

On Windows (PowerShell). pi uses Git Bash for its commands, and its docs
recommend **Windows Terminal**; the plain Git Bash window has display bugs:

```powershell
powershell -c "irm https://pi.dev/install.ps1 | iex"
```

Then start `pi` in any folder, run `/login`, pick a provider, and `/model`.

## Add the workflow and the kit to pi

```bash
~/Gamedev_WF/scripts/install.sh
```

One script, both agents. For pi it does three things:
- links `/start`, `/wrap`, `/judge` and the game commands into
  `~/.pi/agent/prompts/` (pi calls them prompt templates). They are links
  into the kit folder, so `git -C ~/Gamedev_WF pull` is the whole update;
- creates `~/.pi/agent/AGENTS.md`, your user-level "How I work" file, if
  there is none (pi does not read `~/.claude/`). Open it once and fill its
  one bracket;
- runs `pi install ~/Gamedev_WF`, which registers the kit as a pi package for
  the guard extension below.

```bash
pi list
```

should show the kit. Type `/` in pi: `/start`, `/wrap`, `/judge`, `/spec` and
the others must be offered.

## What maps to what

| In this kit | Claude Code | pi |
|---|---|---|
| Standing instructions for a game | `CLAUDE.md` (one line: imports `AGENTS.md`) | `AGENTS.md`, loaded automatically |
| User-level instructions | `~/.claude/CLAUDE.md` | `~/.pi/agent/AGENTS.md` |
| Commands | `/start STA-004`, from `~/.claude/commands/` | `/start STA-004`, from `~/.pi/agent/prompts/` |
| "Ask me before touching my design" | `.claude/settings.json` in the game (`ask` rules) | the guard extension |
| "Never skip the commit gate" | `deny` rules + the git hook | the guard extension + the git hook |
| New task, new session | `/clear` | `/new` |
| Go back to before a wrong attempt | Esc Esc | `/tree` |
| How full is the context | `/context` | the footer, `/session` |
| Run a command yourself and show the agent | `! ./harness/gw.sh cases` | `!./harness/gw.sh cases` (`!!` runs it without sending the output to the model) |

The git pre-commit gate, `gw.sh`, the tests and CI do not care which agent
(or human) is at the keyboard.

## The guard extension

`pi/extensions/gamedev-wf-guard/` is loaded with the package. It only wakes
up in a folder that has `harness/gw.sh`. There it:

- **asks you** before the agent edits anything in `design/` (your documents)
  or `harness/` (the kit's files), and before `git reset --hard`;
- **blocks** `git commit --no-verify` and forced pushes, and tells the model why;
- answers `/guard` with whether it is active.

When pi runs without a window to ask in (`pi -p`), "ask" becomes "block".

It is also the smallest useful example of a pi extension to learn from: the
decisions are a plain function in `rules.ts` with tests (`npm test` in the
kit), and `index.ts` is 60 lines that connect it to pi's `tool_call` event.
Changing a rule is a good first extension exercise.

Limits, so you know what you have: it checks pi's `write`/`edit` tools
exactly, and shell commands by pattern (`rm`, `mv`, `cp`, `sed -i`, `>` into a
protected folder). A determined or confused model can still write a script
that changes a file. Git is the real safety net: `git diff -- design/` before
you commit your own design changes shows anything you did not write.

## A session in pi

```bash
cd ~/games/my-game && pi
```

```text
/start STA-004
```

The agent shows the plan (Gate 1). Answer `OK`. It works until "done when"
passes, reports, and tells you to type:

```text
/wrap
```

Then do the check it names and start a fresh session with `/new`.

Useful while it works: `Enter` sends a correction that is applied at the next
step, `Alt+Enter` queues a follow-up for when it is finished, `Escape` stops
it. `Ctrl+O` expands tool output, `/tree` jumps back to an earlier point and
branches from there, which is the way to undo a wrong attempt without
leaving it in the context.

## Switching between pi and Claude Code on one game

Nothing to convert. Both read `AGENTS.md`, `PROGRESS.md`, the spec and
`docs/QUESTIONS.md`, and both end with `/wrap`, which rewrites PROGRESS.md and
commits. A common split: `/spec` in Claude Code on the Pro allowance, tasks
in whichever agent has budget left.

The two agents keep separate conversation histories. That is fine: the
project's memory is the files, not the chat.

## Check that it works (2 minutes)

The installer is tested (CI installs into an empty home and checks every
link), and the guard's rules are tested. **Loading the commands and the guard
inside a running pi was not possible in the sessions that wrote this**, so do
this once:

1. `pi list` shows the kit.
2. In a game folder outside the kit (for example the copy from
   [08-first-weekend.md](08-first-weekend.md)), start `pi`: the startup
   header lists `AGENTS.md`, and `/` offers `/start`, `/wrap`, `/judge`, `/spec`.
3. `/guard` answers "Guard active".
4. Ask: *"Create design/test.md with one line."* A confirmation dialog must
   appear. Answer no.
5. Ask: *"Run git commit --no-verify -m test."* It must be blocked.

If step 2 offers no commands, run `bash ~/Gamedev_WF/workflow/install.sh --copy ~/Gamedev_WF/commands`
(copies instead of links) and `/reload`. If the extension fails to load, pi
prints the error at startup; paste it to the agent and ask it to fix
`pi/extensions/gamedev-wf-guard/index.ts`.
